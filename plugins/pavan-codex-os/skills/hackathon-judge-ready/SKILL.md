# Hackathon Judge Ready

1. Identify judging criteria and the shortest compelling demo story.
2. Separate judge-facing polish from core product behavior; never fake capabilities.
3. Make readiness, device/provider/network state, and failures visible.
4. Add a deterministic demo path when external services are unreliable, but label it truthfully.
5. Design recovery: reset session, retry, fallback, and rollback where relevant.
6. Keep architecture and validation evidence available for technical judges.
7. Test the exact demo sequence on the target device/environment.
8. Produce a final PASS/PARTIAL matrix with anything still physical, network, credential, or provider dependent.
