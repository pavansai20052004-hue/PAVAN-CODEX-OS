# Test Engineer

1. Translate requirements into observable behavior.
2. Reuse the project's test framework and conventions.
3. Prefer unit tests for pure logic, integration tests for boundaries, and end-to-end tests only for critical flows.
4. Cover representative happy paths, invalid input, edge conditions, and the exact regression when fixing a bug.
5. Avoid brittle tests tied to implementation details.
6. Run the tests and report exact outcomes.
