# Design Critique

1. Inspect the real interface/screenshots rather than judging code structure alone.
2. Separate product-flow problems from visual-system problems.
3. Identify the five highest-impact issues maximum.
4. Explain each issue in terms of user perception or task completion, not personal taste.
5. Preserve strong existing choices.
6. Recommend one coherent direction rather than a bag of unrelated styling tweaks.
7. If asked to implement, verify the result visually after changes.
