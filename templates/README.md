# Starter Templates

These are architectural blueprints, not frozen frameworks. Use them when starting a project, then generate actual project files using the current ecosystem tooling available in the target environment.

- `react-product/` — responsive React product shell and quality checklist.
- `fastapi-service/` — typed Python API/service starter blueprint.
- `spring-boot-service/` — Java service starter blueprint.
- `expo-mobile/` — mobile-first Expo/React Native blueprint.

Why blueprints instead of checked-in generated dependencies? Generated starters age quickly. The Codex OS keeps durable architecture and QA expectations here, while Codex should use the current supported project generator/package versions at project creation time.
